# 两处修复（2026-09-22 深夜，本人报的两个问题）

## 问题 1：功能创造者（pipeline.author）拉不起来

症状
- 本人下令 `talk.py start --role pipeline.author --by me` → 直接抛栈：
  `sqlite3.DatabaseError: not authorized`（File "tools/talk.py", line 334, in set_state）
- 面板上按「开始」也一样起不来（同一段代码路径）。

真因
- 身份判定**两处不一致**：
  - 高层 `_can_control()`（第 325 行）= `self.admin or 有 room:control/write`，**认本人(me)**；
  - 授权器写规则 `_install_guard()` 用的 `admin = self.manage`（第 213 行），
    而 `_can_manage()` 当时只认 `table:role/write` 或 `room:control/write` 的**角色**（即只认经理 owner.me）。
- 于是本人下令：权限检查放行 → 真去写治理表 `room` → 被 SQLite 授权器 DENY → 报 `not authorized`。
  `role / perm / room / stage / member` 这些治理表的写，本人一律写不进去（start / pause / gate-open / stage-add 全中）。

做法
- `_can_manage()` 认本人：`if self.role is None or self.role == "me": return True`（第 187-196 行）。
- 授权器写规则不动 —— 它引用的就是这一个标志，改一处即两处一致。

判据（evidence/本人权限与气泡-修复-20260922.txt）
- 旧代码（备份 talk.py.bak-233920）同一个命令：`not authorized`；
- 修后：`已恢复：pipeline.author（会话本来就在 roles:pipeline-author）`；
- 本人 `stage-add` / `gate-open --by me` 均成功，`gate` 显示「#1 功能开发 pipeline.author ◀ 进行中」；
- `talk_selftest.py` 40 项 OK=40 FAIL=0。

## 问题 2：本人（me）在面板里发的话不进气泡

症状
- 频道页选「你（owner.me）」→ 输入 → 发送：消息确实送达（对端收得到），但**聊天记录里不出气泡**。

真因
- 面板默认以**本人身份**发言（Bridge.kt `talk.say` 的 `by` 默认 `me`），
  而服务端 `thread()`（给面板画气泡的那条查询）把"我说的"**写死成 `from_role='owner.me'`**：
  `... WHERE (from_role='owner.me' AND to_role=?) OR from_role=?`
  → 本人发的（`from_role='me'`）既不满足"我发的"，也不满足"他发的"，直接被漏掉。
- 只有用「身份：经理说」发出去的消息才显示成蓝色气泡 —— 与用户看到的现象完全一致。

做法
- `thread()` 里「我说的」= `('me', 'owner.me')` 两个身份都算（本人与经理都是用户这一侧）。
- **纯服务端改动，不用重编 APK**：手机上回频道页（或重进那个角色）即生效。

判据
- `talk.py thread --role owner.me --lines 200` → count 16，末三条 `631/632/634` 都是 `who=me`（修前这三条根本不在列表里）。
