**症状**：一跑就是全量回归，上下文巨大、判定容易漏；报告只说"复测完成"，说不出"手上到底能不能点到"。

**真因**：测试范围没有边界（全量跑 = 又贵又糊）；只核"逻辑对不对"，没核**坐标 / 键位**这类真机读数。

**做法（本人 2026-09-23 定，权威出处 `roles-chat/SPEC.md` §10）**：
1. **一次只测一块**：板块清单 = ① 聊天页-单聊 ② 聊天页-群聊 ③ 设置页 ④ 网络页 ⑤ 会话页 ⑥ Hermes 页
   ⑦ 左栏/抽屉 ⑧ 频道页（角色列表）。跑**本块用例 + 本块上次改动的回归**，**不跑全量**；
   每块单独驱动文件 + 单独证据文件；只有跨板块改动才跨测，并在报告里写明为什么跨。
2. **坐标**：每个可见控件给 x / y / 宽 / 高（**px 与 dp**）；回答：在不在可视区、有没有被顶栏/键条/键盘遮挡、
   相邻间距是否 ≥44dp、数字有没有被截断。
3. **键位**：命中区 + 点击是否真触发（有没有被别的层吃掉事件）、常驻按键 ≤3、误触高发点点名。
4. **布局形态**：两行制 / 空态 / 折行 / 滚到底 —— 按界面规范逐条核。
5. **截图 + 坐标读数（JSON）一起进证据文件**；报告只给关键数字，并写清**本次只测了哪一块 + 坐标/键位绿了几条**。

**判据**：① 报告里有"本次板块"字样与该块坐标/键位读数；② 证据目录里该块有独立驱动 + 独立 JSON；
③ 没有"顺手全量跑"的痕迹（除非报告说明了跨板块理由）。
