# 当天收工即出包（本人 2026-09-26 定的机制）

## 依据（本人原话 + 频率分析）
本人：「你要**记下我说的话**呀……听我大概说了什么，**分析一下频率** —— 你看我**经常说『打包打包』**，那么你就要比如**每天完成任务就要打包**。」
频率证据：他本人直接说「打包 / APK」**5 次**（09-23 08:41、09-23 08:43「**打包不是这个是生成 apk**」、09-24 21:35「所以打包成 apk 了吗」、09-24 21:36「**我说总的 apk**」、09-26 又一次），**几乎每次都带纠正** ⇒ 说明我们**老要等他开口、还老给错东西**（给单轮包、给 tar.gz）。

## 机制（每天自动，不用他开口）
1. **收工点自动出汇总包**：`hermes-pocket-汇总-<YYYYMMDD>.apk` + **清单**（`已含 / 不含 + 原因`）+ 整包 `sha256` + 包内 `build-info` + **整树对账原始输出**；清单落 `evidence/汇总-<日期>/清单-轮次对照.txt`。
2. **没有新东西就明说**「**今日无新包**」—— **不许硬出旧包糊弄**，也不许沉默。
3. **当天出、当天交**：只要当天有"已收尾的改动"，**当天出包并交本人**，不许攒着、不许等他问。
4. **其他项目同一条**（mark-readnotes / uml-复习手册 / social-archive）：当天有新产物 ⇒ 当天交一份「**今天有什么**」；有出包的当天出包。
5. **定时**：cron 每天 **21:30**（他 19:45–21:25 晚饭+洗澡，21:30 之后才有空看）；**只在真出包或真出问题时出声**，平时不打扰。
6. 口径不变：**打包＝出 APK**；单轮包**保留**（证据/回滚用），**交付只发汇总包**；不新增 tar.gz。

## 判据（经理每天自检）
- 当天 `stage.state='done'` 的轮次列表 vs 当天是否产出 `汇总-<日期>.apk`：**有改动无包 ＝ 我漏了**；
- 清单里每条要写清 `已含 / 不含 + 原因`（如"平台侧修复、App 无改动"「判非缺陷、本来就不该有新包」）；
- 包哈希与字节数**真跑**取（`sha256sum`/`stat`），对账**贴原始输出**，不许只写"PASS"。
