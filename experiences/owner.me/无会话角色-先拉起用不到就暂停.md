name: 无会话角色：先拉起来回话，用不到就暂停
must: true
tags: [经理, 会话, 投递, 内存, 暂停, 调度]
when: 投递台账里出现「无会话」失败、或有角色在等你放行却收不到消息时
verified: 2026-09-23
---
**症状**：投递给某个角色的消息在台账里记成「无会话 失败」，放行通知也投不进去；
角色明明在阶段里挂着，却收不到活、回不了话，本人那边什么都看不到。

**真因**：角色只是**名册里的一行**，它要能收话必须有 tmux 窗口（一个 agent 进程）。
窗口没开＝消息无处落，台账只能记「无会话 失败」。

**做法（本人 2026-09-23 拍定）**：
1. **先把它拉起来**：`python3 tools/talk.py spawn --role <全名>`（幂等，已在跑就不动它），
   确认 `tmux list-windows -t roles` 里有 `<场景>-<角色>` 窗口，然后**重投那条失败的**：
   `talk.py deliver --role <全名> --text "…"` 或 `talk.py relay-once`。
2. **用不到的就暂停，别让它白占内存**（本机内存紧张，一个 agent ≈ 几百 MB）：
   `python3 tools/talk.py pause --role <全名> --by owner.me --hard`（`--hard` 会真的收掉会话）。
   再要用时 `talk.py start --role <全名> --by owner.me`，会顺手把会话开回来。
3. 判断「用不用得到」看三样：它在不在当前 `gate` 的进行中/已放行步骤里、有没有投给它还没回的活、
   有没有等你放行的事项。都没有 → 暂停；有 → 拉起。

**判据**：`talk.py deliveries` 里不再有 ok=0 且 note 含「无会话」的行；
`tmux list-windows -t roles` 里的窗口数 = 当前**真在干活**的角色数（没有闲置窗口长期占内存）。
