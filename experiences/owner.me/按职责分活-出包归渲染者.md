**症状**：一轮活被一个人干完 —— 作者自己改代码、自己出包、自己跑判据出结论；渲染者整轮没派活（pending 挂着），
测试者最后只是"复核一遍作者自己的读数"。本人当场问：「谁做测试，谁做功能，谁做渲染，这个经理没搞明白吗」。

**真因**：排阶段时把「界面绘制 + 出包」整段并进了 author 的步骤里 —— 阶段表里只有 测试 → 按测试结果修 → 复测，
**没有任何一步的 role 是 pipeline.renderer**。三件事（定功能/配方、出包、验）本是三个角色的活，
被我并成两个人甚至一个人 → **自证**：出包的人自己验自己的包，判据没有独立性。

**做法（正解）**：
1. **author**：把「要做什么」写成登记表一行（kind / 位置 / 渲染描述 / 判据 / 测试路径 / **打包配方 pack**），
   改功能、定配方 —— **不做"出包"这个动作**，不拿自己跑的读数当判据。
2. **renderer**：读 pending → 按 hint 画界面 → **按 pack 配方打包** → 把**产物路径与哈希**写回表。
   「出这个包」这一步必须落它头上，阶段表里要单列一步、role = `pipeline.renderer`。
3. **tester**：装 **renderer 出的那个包**（不是作者自出的），按判据真点、独立出结论；通过与否由它说。
4. 排完自己核三样：① 涉及界面/出包的阶段 role 必须是 `pipeline.renderer`；② 派活记录里 `to_role` 覆盖到 renderer；
   ③ 报告里出现「我出的包我自己验的」= 没排开，回去重排。
   **作者自出自测不算把活排开。**

**判据（排完逐条核）**：
- `talk.py gate --project <P>` 里，凡界面/出包那一步的归属角色是 `pipeline.renderer`（并已按顺序放行）；
- `sqlite3 talk.db` 的 delivery/report 里，本轮有投给 renderer 的活、且交付报告里渲染者那条带产物 sha256；
- 交付链是 author（功能+配方）→ renderer（包 + 哈希）→ tester（独立复核），**任何一环缺人就是没排开**。

**已见效的一次**：2026-09-23 `hermes-pocket-测试轮` 第 2 步判完成后，单列第 3 步「渲染出包」放行给 renderer
（`docs/决定-2026-09-23-按职责分活.md`），复测顺位到第 4 步由 tester 做。
