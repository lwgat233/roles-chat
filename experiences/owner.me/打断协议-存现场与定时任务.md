**依据**：本人 2026-09-24 原话「要时常使用定时任务……每次被打断的时候，都要停下来思考一下是不是要把之前的任务给中断，
中断一下，然后中断的时候要做一些整理啊、处理啊，可能下次要继续做之类的」；平台文档 §⑭。

## 一、被打断时（插话/换话题/派新活/急事都算）

1. **先停一下**：判断手上这件事 —— 该**中断**？能并行？还是**直接弃**？不许不声不响切走。
2. **要中断就先存现场**（30 秒，一句话）：
   `做到哪一步 / 下一步该谁 / 未提交改动在哪个文件 / 续跑命令`
   ```
   python3 tools/talk.py scene --role <角色全名> --text "…"   # 存
   python3 tools/talk.py scene                                # 看全部
   ```
3. **顺手整理**：半成品与证据归位（该提交的提交、该落证据的落证据），别留一地散文件。
4. **再切到新事**，并回一句「我把 X 存下了，接着做 Y」。
5. **下次开工先读现场**（`talk.py scene --role …`），照它接着做 —— 不凭记忆。

## 二、定时任务纪律（别靠记性）

- 「到点要做」「要盯着」「要定期报」的事**一律做成 cron**：一次性核对（到点验结果）· 常驻哨兵（只在出问题时说话）· 周期汇报。
- **判据**：说过「我稍后去核 / 明天看」必须**当场**变成 cron（`next_run_at` 就是凭据）；**没建任务＝没答应**。
- 哨兵一律「**空输出＝不打扰**」（`no_agent` + 脚本，只在越线时输出），省 token 又不刷屏。
- 平台现有三件：**12:00 无指示续活**（noon-resume.py）· **收工哨兵**（offwork-sentinel.py，每 20 分钟）·
  **预算哨兵**（budget-sentinel.py，每 30 分钟：到 ¥10 报一次、到 ¥15 再报一次，当天不重复）。
