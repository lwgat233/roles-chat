# 交活必须走 `report`，不许只 reply

## 现象（2026-09-25 踩到，平台级老坑）
我把三样东西（两份功能介绍 + 社媒#1 报告）**挂成了派活那条消息的回复**（`reply --id 1402`），
文字里还写了"报告在此"。结果：
- 经理的待办/inbox 里**看不见它**（回复不进对方 inbox）；
- 两个项目的闸门一直 **◀ 进行中**（没有合格的报告行，经理按规矩判不了 `gate-done`）；
- **本人那边一点通知都没有** —— 东西齐了却卡在中间，他直接问"怎么没通知"。

## 正确做法
交活一律：
```
python3 tools/talk.py report --project <项目名> --seq <步号> --from <你的全名> --text "<报告正文>"
```
（正文长就先写文件，再 `--text "$(cat 文件)"`；`--project/--seq` 必须**照派活里写的项目名与步号**填，错一个字闸门就匹配不上。）
- `report` **不用写收件人** —— 平台自己投给经理（owner.me）；报告行会被 `gate-done` 认；
- 想再多说一句可以**另外再 reply**，但**报告本体必须在 report 通道**；
- 交完自己核一眼：`python3 tools/talk.py gate | grep <项目名>` —— 该步还在"进行中"就说明没交到正确的项目/步号上。

## 规矩
- **报告 = `report`**；**reply = 对话**。两者别混。
- 只管 reply 就以为交了活 ⇒ 等于**没交**。
- 作者/渲染者那边也踩过同一个坑（记过的老坑），凡是"交活"这一步都按上面来。
