## ① 固定周期，各层级问一遍「完成怎样」

- **谁问谁**：按现有层级，不跨级 —— 女仆→经理，经理→各角色。
- **周期**：固定周期，具体值由经理定并写进对话（建议 30–60 分钟一次）；同一周期内别重复问同一人。
- **只问三句**：手上这步完成怎样 / 卡在哪 / 要什么。
- **落点**：问与答都要进对话（面板上能看见），别在 tmux 里问一句就当问过了。
- **判据**：一个周期内，对话里能看到"问"的记录；被问的人没回，按现有 `nudge`（45 分钟、最多 2 次）追问并升级给本人。

## ② pipeline 层之间允许直接对话 —— 但优先「写文件对接」

- pipeline.author / renderer / tester 之间**允许直接对话**，不必事事经经理。
- **首选交接方式：写本地文件**（同一台 NAS 上；路径与哈希写在交付里）。大段内容（打包配方、判据清单、产物清单）走文件比走对话更合适。
- **明确不要求**：不要为"文件对接"再造一套投递回执/台账 —— 文件只是更好的对接方式，不追踪每条信息的发送。
- **必须走对话的**：要本人或经理知道的事（派活、放行、报告、卡住、越界），照旧进对话。
- **判据**：交接物能在文件里对上（路径 + 哈希）；对话里只留"做了 / 交了 / 卡住"这类结论，不贴大段正文。

## ③ 聊天（对话通道）要求实时

- 角色说的话、进度、放行、报告，要及时出现在面板/对话里，**不许攒着批量补**。
- **判据**：一次对话事件从产生到面板可见的延迟可测（用时间戳对比），而不是等下一轮一起写。

## ④ 没有聊天时，闲置角色不许动

- 没在执行任务的角色：**不做任何事** —— 不刷屏、不自行开工、不主动发消息、不"顺手看看"。
- **唯一的例外**：向经理提出申请，**且经理认为合理**（两条同时满足才准动）。
- **判据**：对话里若出现"未派活角色自己发起的消息"，要能查出：该角色名下没有 `active` 阶段、也没有经理的批准记录 —— 那就是违规（记进它的经验）。

## ⑥ 本人不在时（没回答 / 睡了）怎么定调

本人原话：「如果我没回答，或者我睡了，那么就讨论完后自己觉得，可以是 pipeline 直接进行讨论，

**可用形状（细节由经理定，这版给个能直接跑的）**：

2. **讨论**：pipeline 层之间**直接讨论** —— 走文件（见 ②），不刷对话、不等经理转话。
3. **经理写文件**：把议题与结论落成一份**决定书**，放项目 `docs/` 下，命名
   `决定-<日期>-<议题>.md`，内容：议题 / 候选 / 各自理由与依据（引用证据路径）/ 最终结论 / 生效范围。
4. **投票定调**：参与的 pipeline 角色**一人一票**（author / renderer / tester 各一票），票写进同一份文件；

5. **平票 / 没人投**：经理按总目标（省流量 · 省电 · 方便）取**保守那一档**，并在文件里写明"平票由经理定"。

**判据**：本人不在时如果改了方向，必须能拿出这份决定书（议题、票、结论齐全）；没有 = 违规。

**状态登记（别靠猜）**：本人不在时，状态写在 `talk.db` 的 `setting` 里 ——
`owner_away=1`、`owner_away_since=<时间戳>`、`owner_away_note=<一句说明>`。
角色/经理要判断"现在能不能等他回话"，读这三个键，不要凭"发了没回"猜。
**注意**：`owner_away=1` 只表示"不回话"，**不代表不通知** —— 该推 QQ/手机照推。

## ⑦ 省 token 纪律 + 每次任务记 token（本人补充，2026-09-23）

本人原话：「经理尽量要求他们省 token，并统计每次任务耗费 token」。

**A. 省 token 纪律（经理要求各角色照做）**

  每行一件事；判据只留"数字 + 结论"，**原始输出进证据文件**（对话里不贴）；超 8 行 = 不合格。
- **标题必须明确**：标题里就能看出是哪个项目哪一步、谁交的、几点交的 —— 不许写「【告知】进度」这种糊标题。
- **进度通知只报刚动的项目**（`progress_line(project=…)`），没变的不列。
- **成本一律用人民币**：`¥ = 美元估算 × cny_per_usd`（默认 **7.2**，存在 `talk.db`
  的 `setting.cny_per_usd`）。报告末行写：`本次任务：调用 N 次 · 输入 X · 输出 Y · 缓存读 Z · ≈¥W`。
- 回答短：只给结论 + 关键数字，不贴大段正文（大段内容走文件，见 ②）。
- 不重复劳动：同一份大文件不反复整读（先看目录/段落）；只在改动范围里检索。
- 不回放日志：交付里给**证据路径 + 哈希**，不要把原文粘进对话。
- 报告只写"做了什么 / 判据 / 证据路径 / 卡在哪"，不写过程叙事。

**B. 每次任务记 token（机制已具备，照这个取数）**

- 每个角色 = **一条长命的 Hermes 会话**（`~/.hermes/state.db`）。会话 id 用角色名取：
  `SELECT id FROM sessions WHERE title='pipeline.author';`
- 用量在 `session_model_usage`，按 `session_id` 累计：
  `api_call_count / input_tokens / output_tokens / cache_read_tokens / cache_write_tokens /
   reasoning_tokens / estimated_cost_usd / actual_cost_usd`（还有 `task` 列可打标签）。
- **一次任务的用量 = 任务开始前、结束后各读一次，取差值**（角色会话长命，直接读累计会算进历史）。
  取数命令（把 `<会话id>` 换掉；换算成"这次任务"就用两次读数相减）：

```
sqlite3 ~/.hermes/state.db "SELECT SUM(api_call_count), SUM(input_tokens), SUM(output_tokens),
       SUM(cache_read_tokens), ROUND(SUM(estimated_cost_usd),4)
  FROM session_model_usage WHERE session_id='<会话id>';"
```

- **交付四样加一行**：`本次任务 token：调用 N 次 · 输入 X · 输出 Y · 缓存读 Z · ≈$W`
- **判据**：① 每个角色的交付报告里都有这一行；② 数字能从 state.db 复算出来（给出会话 id 与两次读数）；
  ③ 经理那侧要有取数入口（建议 `talk.py usage --role <全名> [--since <时间>]` 之类），别靠人手抄。

## ⑭ 打断协议 + 常用定时任务（本人 2026-09-24 定）

本人原话：「要时常使用定时任务……每次被打断的时候，都要停下来思考一下是不是要把之前的任务给中断，
中断一下，然后中断的时候要做一些整理啊、处理啊，可能下次要继续做之类的」

**A. 被打断时（任何打断：本人插话 / 换话题 / 派新活 / 来了急事）**
1. **先停一下**，判断手上这件事：该**中断**？能并行？还是直接弃？——别不声不响就切走。
2. **要中断就先"存现场"**（一句话，30 秒写完）：做到哪一步 / 下一步该谁 / 未提交改动在哪个文件 / 续跑命令。
   落点：`talk.py scene --role <角色> --text "…"`（表 `scene`）。
3. **顺手整理**：半成品与证据归位（该提交的提交、该落证据的落证据），别留一地散文件。
4. **再切到新事**，并回一句"我把 X 存下了，接着做 Y"。
5. **下次开工先读现场**：`talk.py scene --role <角色>`（或 `talk.py scene` 看全部），照它接着做。

**B. 常用定时任务（别靠记性）**
- "到点要做""要盯着""要定期报"的事，一律做成 cron：**一次性核对**（到点验结果）、
  **常驻哨兵**（只在出问题时说话）、**周期汇报**。
- 判据：说过的"我稍后去核 / 明天看"必须**当场**变成 cron（`next_run_at` 就是凭据）；没建任务＝没答应。

**C. 自查判据**
- 打断之后：`scene` 表里查得到那句现场（谁 / 何时 / 什么）；
- 下次继续：能看到"照现场接着做"的记录；
- 答应过的核对：cron 列表里找得到。
