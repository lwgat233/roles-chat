## 议题
`hermes-pocket-测试轮` 的阶段表把「界面绘制 + 出包」并进了 author 的步骤里 ——
阶段只有 测试(tester) → 按测试结果修(author) → 复测(tester)，**没有任何一步的 role 是 pipeline.renderer**。
后果：author 从改 `stamp-build.py`/`build.sh` 一路做到出 APK、还自己跑本地测试台出判据（**自证**）；
renderer 整轮没收到活（最后一次收到活 09-22 22:46，pending 7 一直挂着）。

## 候选
- **A（选它）**：按职责拆成三个角色各自一步 —— author 交「功能改动 + 打包配方(pack)」，
  renderer 按配方出包并把产物路径与哈希写回，tester 装 **renderer 出的那个包**独立复测。
- B：维持原样（author 一路做到出包 + 自测）。→ 判据没有独立性，且 renderer 长期空转，等于角色白设。
- C：author 只写配方，出包与复测都并给 tester。→ 出一版包要跑构建链、装包真点，测试者干两份活，不成。

## 理由与证据路径
- 角色职责定义：`~/.hermes/skills/roles/pipeline/references/角色职责与交接.md`（author 定功能/配方、renderer 画界面与打包、tester 真点复核）。
- 本轮实况（台账与报告）：报告 `#743`（author 的交付里同时出现"我出的包"与"我跑的判据"）；
  投递台账 `delivery` 里 renderer 本轮无派活记录；`talk.py gate --project hermes-pocket-测试轮` 原本 0 步 role=renderer。
- 经验（我方必读）：`experiences/owner.me/按职责分活-出包归渲染者.md`。

## 结论
1. 本轮阶段表已改：`hermes-pocket-测试轮` = ①测试(tester)✔ ②按测试结果修(author)✔ ③**渲染出包(renderer)◀ 进行中** ④复测(tester)🔒。
2. 第 2 步按「功能改动 + 配方」判完成；author 自出的包（`apk/测试版/hermes-pocket-版本串每包更新-20260923.apk`）
   与它自己跑的读数**只算过程材料**，不作交付、不作判据。
3. 复测对象 = renderer 按配方重出的那一版；判据由 renderer 写回哈希、tester 独立复核。
4. 已派活给 renderer（`#749`，投递 ok=1），口径更正已同步 author（`#750`，投递 ok=1）。

## 生效范围
