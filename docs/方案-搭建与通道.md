# 方案：搭建方式与客户端↔服务端通道

（2026-09-22 记。**这份是方案，不是已经做完的东西**；标注「已实现 / 先不做」的地方请照标注看。）

roles-chat（服务端）与 hermes-pocket（客户端）是**互为表里的一对**：
服务端管角色名册、经验库、带权限的对话、阶段闸门、女仆中转；客户端是手机上那个「频道」页。
下面按 现在 → 近期 → 以后 三段写。

---

## 一、现在（已实现，可复现）

**一键搭建**
```bash
bash roles-chat/install-all.sh          # 这一对：服务端 + 客户端 APK
POCKET_DIR=/别的地方/hermes-pocket SKIP_CLIENT=1 bash install-all.sh   # 只搭服务端
```
- 服务端 `install.sh`：建库 → 从 `talk/*.md` 重建 → 经验自检 → 权限自检（31 项）
- 客户端 `tools/build.sh`：只用本机工具链编 APK（JAVA_HOME / ANDROID_HOME / GRADLE_BIN 可覆盖）

**通道**：客户端 SSH 到 NAS → 跑 `talk.py` 子命令 → 读 stdout/JSON。
**建角色**：客户端「频道」页 →「＋ 新角色」→ 场景 / 角色名 / 描述 / 标签 → 建（走 `talk.reg`）。

## 二、近期（建议先做）：客户端一键自搭建服务端

**要的东西**：手机上登录 SSH 之后，在 pocket 里点一次，服务端就装好。
（你 2026-09-22 提的：「登录了 ssh 之后…让他能够完成自搭建这个 roles-chat」。）

**做法（两步都能落地，先做 A）**
- A. **仓库已在服务器上**（常见）：客户端执行 `cd <roles-chat> && bash install.sh`，把最后 N 行回显到面板。
- B. **仓库不在服务器上**：客户端先 `git clone <repo> <目录>` 再执行 install.sh。
  （离线机器：客户端把源码打包推过去——这条按需再做。）

**面板上的样子（全按键）**：频道页多一个「搭服务端」键 → 点一下 → 显示「正在装…」→ 成功显示自检 31/31，失败显示最后几行。
另外显示一行状态：`服务端在 <路径>，自检 31/31`（没装就显示「还没装」）。

**判据（能算做完）**
1. 新机器上：客户端 SSH 登录 → 点一次「搭服务端」→ 服务端自检 31/31 通过、`roles-json` 能取到。
2. 同一条命令再点一次不会坏事（**幂等**：库在就不重建、缺就从 `talk/*.md` 补）。
3. 失败时面板上能看到原因（最后 5~10 行），不是只有「失败」两个字。

**已知要注意的**
- **不要 sudo**：你账号没有免密 sudo，全部装在用户目录；路径用 `ROLES_CHAT_HOME` 覆盖。
- **不要把口令/token 拼进命令行**（会进 shell history / 服务端日志）——要传就用文件或 stdin。
- **只执行仓库里的 `install.sh`**，不要执行面板传来的任意文本（否则面板变成远程执行口）。
- 依赖：`talk.py` **只用 Python 标准库** ✓（NAS 上 Debian 12 的 python3 直接够），不需要 pip/联网。
- 装完要 `chmod 644 talk.db`（踩过：库权限被弄成 000，SQLite 报成 `disk I/O error`）。

## 三、以后（你说先不做）：HTTP 通道 / HTTP 搭建

### 为什么值得做
- SSH 通道的代价：服务器得开 SSH、手机上得放密钥；RPC 靠**解析 CLI stdout**（脆）；
  轮询走 SSH 开销大；将来非 Android 客户端（网页/桌面）没法复用。
- HTTP 之后：客户端只要「地址 + token」，不碰密钥；接口是 JSON，稳。

### 目标接口（服务端加 `tools/talk_server.py`，**仍只用标准库** `http.server`）
```
GET  /health                      存活 + 版本
GET  /roles                       场景分组的角色 + 谁在线 + 能接入哪些频道（= 现有 roles-json）
GET  /asks                        谁在等你授权（= asks-json）
GET  /members                     接入表（频道 → 谁能收到）
GET  /since?after_id=N            增量拉消息（面板轮询用）
POST /send    {to,kind,topic,body,scope}
POST /reply   {id,body}
POST /reg     {scene,name,title,tags}
POST /answer  {id,text}
POST /wake-ok | /wake-skip {id,roles}
```
- **权限模型不变**：真正的隔离仍在 `talk.py` 的 SQLite authorizer 与 `v_msg` 视图；
  HTTP 层只做「**token → 角色**」映射，然后按那个角色连库。
- token 放 `config.json`（**不入档、不进 git**）；默认**只监听局域网**。

### 一键搭建怎么变
```bash
bash install.sh            # 现在这样：只装库
bash install.sh --http     # 装完顺带起服务（systemd --user unit 或 nohup），打印 http://<局域网IP>:8787
```
客户端那边：填「地址 + token」就能用，**SSH 变成可选**。

### 共存与迁移（重要）
- 客户端加一层 **Transport 抽象**（`ssh | http`），面板里可切：SSH 保底、HTTP 首选。
  现在面板里所有按钮都走同一个 `rpc(op,args)`，换成 Transport 是**一处改动**。
- 服务端两条通道并存不冲突（都是连同一个 `talk.db`，只是入口不同）。

### 鸡生蛋的问题（要写清）
HTTP 通道建好之后，**“第一次搭建”仍然需要一次终端/SSH**（或走 fnOS 应用、或一个 bootstrap 脚本）——
服务还没起来之前没有 HTTP 可打。所以第二节那个「客户端 SSH 自搭建」不是过渡废物，它会长期留着当**引导(引导安装)**。

### 未知点 / 风险（动手前要先试的）
1. **Android 明文 HTTP**：WebView/OkHttp 默认禁明文 → 要么 `cleartextTrafficPermitted`（局域网），要么自签 TLS（还得信任证书）。→ 先试局域网明文，再决定 TLS。
2. **实时性怎么做**：轮询 `/since` 还是 SSE？SSE 在 WebView 里可用，但耗电/断线重连要实测。
3. **并发写 SQLite**：HTTP 会并发来请求 → 单写者模型 + `busy_timeout`，写操作串行化（否则 `database is locked`）。
4. **谁能改治理表**（role/perm/member/stage）：只有 token 对应的经理身份，普通角色 token 一律拒。
5. **要不要出公网**：按你「尽量不依赖外网」的偏好，**先只做局域网**；要出网再谈反代 + 证书 + 限流。

### 判据（能算做完）
1. 关掉 SSH 也能：看角色/谁在线、谁在等你授权、建角色、答授权、收发消息。
2. 服务端自检仍然 **31/31**（HTTP 不改变权限结论）。
3. 权限结论不变：第三方 `GET /since` 拿不到私信；经理拿不到私信内容；本人（token=owner）拿到全部。
4. 客户端不再需要 SSH 密钥（可以从设置里删掉密钥仍能连）。

## 四、成本粗估（给你排期用）

| 事 | 位置 | 量 |
|---|---|---|
| 客户端「搭服务端」一键 | 客户端 1 个键 + 服务端 `install.sh` 幂等化 | 小（半天内） |
| `talk_server.py`（上面 8 个接口） | 服务端新文件 | 中（约 250 行，标准库） |
